# ADR 002 — Mock-First 구현 전략

날짜: 2026-05
상태: 결정됨

---

## 맥락

6개 노드를 동시에 개발하면 통합 테스트 전까지 파이프라인 전체를 실행해볼 수 없습니다.

## 결정

모든 노드는 **mock 구현 상태로 먼저 통합**하고, 이후 실제 LLM 구현으로 교체합니다.

## 구현 방식

각 노드 파일은 아래 구조를 유지합니다:

```python
def run(state: PatentAgentState) -> dict:
    # ── mock ─────────────────────────────────────────────────────────────
    return {"필드": "mock 값"}
    # ── 실제 구현 위치 ────────────────────────────────────────────────────
    # 실제 구현 코드
```

## 이유

- 파이프라인 전체 흐름을 팀 전체가 즉시 실행·확인 가능
- 노드별로 독립적으로 실제 구현 교체 가능 (타 노드 구현 완료를 기다리지 않아도 됨)
- mock이 실제와 동일한 키를 반환하므로 테스트 코드 재사용 가능

## 결과

- CLAUDE.md 섹션 8의 구현 상태 표를 최신 상태로 유지
- mock → 실제 구현 교체 시 `# ── mock ──` 블록 제거, PR 설명에 명시
