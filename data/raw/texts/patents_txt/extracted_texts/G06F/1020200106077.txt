기 술 분 야
본 발명의 실시예들은 메모리 시스템, 메모리 컨트롤러 및 메모리 시스템의 동작 방법에 관한 것이다.
[0001]
배 경 기 술
저장 장치에 해당하는 메모리 시스템은 컴퓨터와, 스마트 폰, 태블릿 등의 모바일 단말, 또는 각종 전자 기기와
[0002]
같은 호스트(host)의 요청을 기초로 데이터를 저장하는 장치이다. 메모리 시스템은 하드 디스크 드라이브(HDD:
Hard  Disk  Drive)와 같이 자기 디스크에 데이터를 저장하는 장치뿐 아니라,  솔리드 스테이트 드라이브(SSD:
Solid State Drive), UFS(Universal Flash Storage) 장치, eMMC(embedded MMC) 장치 등과 같이 비휘발성 메모
리에 데이터를 저장하는 장치 등을 포함할 수 있다. 
메모리 시스템은 메모리 장치(e.g. 휘발성 메모리/비휘발성 메모리)를 제어하기 위한 메모리 컨트롤러를 더 포
[0003]
함할 수 있으며, 이러한 메모리 컨트롤러는 호스트로부터 커맨드(Command)를 입력 받아, 입력 받은 커맨드에 기
초하여 메모리 시스템에 포함된 메모리 장치에 데이터를 리드(Read), 라이트(Write), 또는 소거(Erase) 하기 위
한 동작들을 실행하거나 제어할 수 있다. 그리고 메모리 컨트롤러는 이러한 동작들을 실행하거나 제어하기 위한
논리 연산을 수행하기 위한 펌웨어를 구동할 수 있다.
메모리 시스템은 메모리 장치에 데이터를 리드, 라이트, 소거하는 동작을 실행하기 위한 맵 데이터를 관리한다.
[0004]
메모리 시스템은 맵 데이터를 빠르게 액세스하기 위해 맵 데이터를 캐싱하는 맵 캐시를 사용한다. 메모리 시스
템은 맵 캐시에 캐싱된 맵 데이터를 업데이트한 후에, 특정한 조건이 만족될 때 맵 캐시에 캐싱된 맵 데이터를
메모리 장치로 플러시(flush)한다. 이때, 맵 데이터를 메모리 장치로 플러시하는 동작과 호스트가 요청한 리드
동작 또는 라이트 동작이 동시에 실행될 경우, 호스트가 요청한 리드 동작 또는 라이트 동작의 성능이 저하되어
QoS를 만족하지 못하는 문제가 발생할 수 있다.

해결하려는 과제
본 발명의 실시예들은 맵 데이터가 메모리 장치에 집중적으로 플러시되어 발생하는 리드 동작 및 라이트 동작의
[0005]
성능 저하를 완화할 수 있는 메모리 시스템, 메모리 컨트롤러 및 메모리 시스템의 동작 방법을 제공할 수 있다.
또한 본 발명의 실시예들은 호스트가 요청한 리드 동작 및 라이트 동작에 대한 QoS를 만족시킬 수 있는 메모리
[0006]
시스템, 메모리 컨트롤러 및 메모리 시스템의 동작 방법을 제공할 수 있다.

플래시 변환 계층의 주소 맵핑 방법에는 맵핑 단위에 따라 여러 가지가 있다. 대표적인 어드레스 맵핑 방법에는
[0041]
페이지 맵핑 방법(Page  mapping  method),  블록 맵핑 방법(Block  mapping  method),  그리고 혼합 맵핑 방법
(Hybrid mapping method)이 있다.
프로세서(124)는 호스트(HOST)로부터 수신된 데이터를 랜더마이즈하도록 구성된다. 예를 들면, 프로세서(124)는
[0042]
랜더마이징 시드(seed)를 이용하여 호스트(HOST)로부터 수신된 데이터를 랜더마이즈할 것이다. 랜더마이즈된 데
이터는 저장될 데이터로서 메모리 장치(110)에 제공되어 메모리 셀 어레이에 프로그램 된다.
프로세서(124)는 읽기 동작 시 메모리 장치(110)로부터 수신된 데이터를 디랜더마이즈하도록 구성된다. 예를 들
[0043]
면, 프로세서(124)는 디랜더마이징 시드를 이용하여 메모리 장치(110)로부터 수신된 데이터를 디랜더마이즈할
것이다. 디랜더마이즈된 데이터는 호스트(HOST)로 출력될 것이다.
프로세서(124)는 펌웨어(FirmWare)를 실행하여 메모리 컨트롤러(120)의 동작을 제어할 수 있다. 다시 말해, 프
[0044]
로세서(124)는, 메모리 컨트롤러(120)의 제반 동작을 제어하고, 논리 연산을 수행하기 위하여, 부팅 시 워킹 메
모리(125)에 로딩 된 펌웨어를 실행(구동)할 수 있다. 
펌웨어(FirmWare)는 메모리 시스템(100) 내에서 실행되는 프로그램으로서, 다양한 기능적 레이어들을 포함할 수
[0045]
있다. 
예를 들어, 펌웨어는, 호스트(HOST)에서 메모리 시스템(100)에 요구하는 논리 주소(Logical Address)와 메모리
[0046]
장치(110)의 물리주소(Physical Address) 간의 변환 기능을 하는 플래시 변환 레이어(FTL: Flash Translation
Layer)와, 호스트(HOST)에서 저장 장치인 메모리 시스템(100)에 요구하는 커맨드를 해석하여 플래시 변환 레이
어(FTL)에 전달하는 역할을 하는 호스트 인터페이스 레이어(HIL: Host Interface Layer)와, 플래시 변환 레이어
(FTL)에서 지시하는 커맨드를 메모리 장치(110)로 전달하는 플래시 인터페이스 레이어(FIL: Flash  Interface
Layer) 등 중 하나 이상을 포함할 수 있다. 
이러한 펌웨어는, 일 예로, 메모리 장치(110)에 저장되어 있다가 워킹 메모리(125)에 로딩 될 수 있다. 
[0047]
워킹 메모리(125)는 메모리 컨트롤러(120)를 구동하기 위해 필요한 펌웨어, 프로그램 코드, 커맨드 또는 데이터
[0048]
들을 저장할 수 있다.  이러한 워킹 메모리(125)는, 일 예로,  휘발성 메모리로서,  SRAM  (Static  RAM),  DRAM
(Dynamic RAM) 및 SDRAM(Synchronous DRAM) 등 중 하나 이상을 포함할 수 있다. 
에러 검출 및 정정 회로(126)는 에러 정정 코드(Error Correction Code)를 이용하여 확인 대상 데이터의 에러
[0049]
비트를 검출하고, 검출된 에러 비트를 정정하도록 구성될 수 있다. 여기서, 확인 대상 데이터는, 일 예로, 워킹
메모리(125)에 저장된 데이터이거나, 메모리 장치(110)로부터 읽어온 데이터 등일 수 있다.

도 5를 참조하면, 메모리 컨트롤러(120)는 복수의 맵 캐시 풀들(MC_POOL) 각각에 대응하는 타이머를 서로 다르
[0118]
게 설정할 수 있다.
일 예로, 메모리 컨트롤러(120)는 어느 하나의 맵 캐시 풀에 대해, 해당 맵 캐시 풀에 캐싱된 맵 데이터가 시간
[0119]
T1마다 메모리 장치(110)로 플러시되도록 타이머를 설정할 수 있다.
그리고 메모리 컨트롤러(120)는 다른 맵 캐시 풀에 대해, 해당 맵 캐시 풀에 캐싱된 맵 데이터가 시간 T2마다
[0120]
메모리 장치(110)로 플러시되도록 타이머를 설정할 수 있다.
그리고 메모리 컨트롤러(120)는 또 다른 맵 캐시 풀에 대해, 해당 맵 캐시 풀에 캐싱된 맵 데이터가 시간 T3마
[0121]
다 메모리 장치(110)로 플러시되도록 타이머를 설정할 수 있다.
이와 같이 메모리 컨트롤러(120)는 복수의 맵 캐시 풀들(MC_POOL) 각각에 대응하는 타이머를 서로 다르게 설정
[0122]
함으로써, 맵 캐시(MAP_CACHE)에 캐싱된 맵 데이터가 메모리 장치(110)에 플러시되는 시점을 분산시킬 수 있다.
이를 통해, 메모리 컨트롤러(120)는 맵 캐시(MAP_CACHE)에 캐싱된 맵 데이터가 메모리 장치(110)에 집중적으로
[0123]
플러시하면서 발생하는 문제를 방지할 수 있다.
일반적으로 호스트로부터의 리드 요청 및 라이트 요청은 일정하게 메모리 컨트롤러(120)에 입력된다. 만약, 메
[0124]
모리 컨트롤러(120)가 맵 캐시(MAP_CACHE)에 캐싱된 맵 데이터를 메모리 장치(110)에 플러시하기 위해 많은 리
소스(e.g. 워킹 메모리(125)의 공간)를 사용하게 되면, 호스트로부터 수신한 리드 요청 또는 라이트 요청을 처
리하는 데 사용 가능한 리소스가 부족하여 처리 성능이 감소하고, 이로 인해 호스트가 요청한 리드 동작 및 라
이트 동작에 대한 QoS를 만족시키지 못하는 문제가 발생할 가능성이 높아진다.
따라서, 메모리 컨트롤러(120)는 이러한 문제를 방지하기 위해, 대량의 맵 데이터가 메모리 장치에 집중적으로
[0125]
플러시되지 않도록 맵 캐시(MAP_CACHE)에 캐싱된 맵 데이터가 메모리 장치(110)에 플러시되는 시점을 타이머를
이용하여 분산시킬 수 있다. 이를 통해 메모리 시스템(100)은 맵 데이터가 메모리 장치에 집중적으로 플러시되
어 발생하는 리드 동작 및 라이트 동작의 성능 저하를 완화하여, 호스트가 요청한 리드 동작 및 라이트 동작에
대한 QoS를 만족시킬 수 있다.
이상에서, 맵 캐시(MAP_CACHE) 내부에 복수의 맵 캐시 풀들(MC_POOL)을 설정하여 각 맵 캐시 풀마다 맵 데이터
[0126]
를 분산해서 플러시하는 이유에 대해 설명하였다.
이하,  맵 캐시(MAP_CACHE)  내부에 복수의 맵 캐시 풀들(MC_POOL)을 설정하는 방법의 일 예를 도 6에서
[0127]
설명한다.
도 6은 본 발명의 실시예들에 따른 메모리 시스템(100)이 각 맵 캐시 풀의 영역을 설정하는 방법의 일 예를 나
[0128]
타낸 도면이다.
도 6을 참조하면, 메모리 시스템(100)의 메모리 컨트롤러(120)는 맵 캐시(MAP_CACHE) 내부에 복수의 맵 캐시 풀
[0129]
들(MC_POOL)을 설정하기 위해, 복수의 맵 캐시 풀들(MC_POOL) 각각의 영역을 지시하는 레지스터들(REG)의 값을
설정할 수 있다.
이때,  레지스터들(REG)에 저장되는 값을 설정하는 방법은 다양하게 결정될 수 있다.  일 예로 각 레지스터들
[0130]
(REG)은 대응하는 맵 캐시 풀의 시작 주소 및 종료 주소의 값을 저장할 수 있다. 다른 예로 각 레지스터들(RE
G)은 대응하는 맵 캐시 풀의 시작 주소 및 사이즈의 값을 저장할 수 있다.

--- [페이지 구분] ---

이하, 메모리 컨트롤러(120)가 복수의 맵 캐시 풀들(MC_POOL) 각각에 대응하는 타이머를 설정하는 구체적인 실
[0131]
시예를 설명한다.
예를 들어, 메모리 컨트롤러(120)는 복수의 맵 캐시 풀들(MC_POOL) 각각에 대응하는 타이머를 각 맵 캐시 풀에
[0132]
캐싱되는 맵 데이터의 타입에 따라 다르게 설정할 수 있다. 즉, 메모리 컨트롤러(120)는 복수의 맵 캐시 풀들
(MC_POOL) 중 제1 맵 캐시 풀(MC_POOL_1)에 대해, 제1 맵 캐시 풀(MC_POOL_1)에 대응하는 타이머를 제1 맵 캐
시 풀(MC_POOL_1)에 캐싱되는 맵 데이터의 타입에 따라 설정할 수 있다.
본 발명의 실시예들에서, 맵 데이터의 타입은 일 예로 다음과 같이 구분될 수 있다.
[0133]
1. L2V 데이터 타입
[0134]
L2V 데이터 타입인 맵 데이터는, 호스트에서 전송된 논리 주소(LA, logical address)와 메모리 장치(100)의 가
[0135]
상의 물리적 주소(VA, virtual address) 간의 매핑 관계를 지시하는 데이터이다. 이때, 가상의 물리적 주소는
가상 플래시 메모리의 물리적 어드레스에 대응하는데, 이는 가상 플래시 계층에 의해 메모리 장치(110)의 물리
적 주소에 대응할 수 있다.
2. VPT 데이터 타입
[0136]
VPT 데이터 타입인 맵 데이터는, 맵 데이터가 지시하는 주소에 위치한 페이지가 유효한(valid) 페이지인지 여부
[0137]
를 지시하는 데이터이다.
3. 저널링 데이터 타입
[0138]
저널링 데이터 타입인 맵 데이터는, 맵 데이터의 변경 사항을 지시하는 데이터로서, 맵 데이터의 변경 이력을
[0139]
추적하는데 사용될 수 있다.
4. 기타 데이터 타입
[0140]
기타 데이터 타입인 맵 데이터는, 전술한 L2V 데이터, VPT 데이터, 저널링 데이터를 제외한 나머지 정보(e.g.
[0141]
각 메모리 블록 별 리드 카운트, 소거 카운트)를 지시하는 데이터이다.
도 7은 본 발명의 실시예들에 따른 각 맵 캐시 풀에 캐싱되는 맵 데이터의 타입의 일 예를 나타낸 도면이다.
[0142]
맵 캐시(MAP_CACHE)에 포함된 복수의 맵 캐시 풀들(MC_POOL)은 각각 서로 다른 타입의 맵 데이터를 캐싱할 수
[0143]
있다. 도 7에서, 복수의 맵 캐시 풀들(MC_POOL)은 각각 L2V 데이터 타입, VPT 데이터 타입 및 저널링 데이터 타
입의 맵 데이터를 캐싱할 수 있다.
메모리 컨트롤러(120)는 복수의 맵 캐시 풀들(MC_POOL) 중 L2V 데이터 타입의 맵 데이터를 캐싱하는 맵 캐시 풀
[0144]
에 대해 제1 타이머(TIMER_1)를 설정할 수 있다.
메모리 컨트롤러(120)는 복수의 맵 캐시 풀들(MC_POOL) 중 VPT 데이터 타입의 맵 데이터를 캐싱하는 맵 캐시 풀
[0145]
에 대해 제2 타이머(TIMER_2)를 설정할 수 있다.
메모리 컨트롤러(120)는 복수의 맵 캐시 풀들(MC_POOL) 중 저널링 데이터 타입의 맵 데이터를 캐싱하는 맵 캐시
[0146]
풀에 대해 제3 타이머(TIMER_3)를 설정할 수 있다.
이상에서, 메모리 컨트롤러(120)가 맵 캐시 풀에 캐싱되는 맵 데이터의 타입에 따라 타이머를 설정한다는 내용
[0147]
을 설명하였다.
이하, 메모리 컨트롤러(120)가 맵 캐시 풀에 캐싱되는 맵 데이터의 타입에 따라 타이머의 값을 설정하는 구체적
[0148]
인 실시예들을 설명한다.
일 예로, 메모리 컨트롤러(120)는 복수의 맵 캐시 풀들(MC_POOL) 중 제1 맵 캐시 풀(MC_POOL_1)에 대응하는 타
[0149]
이머를 설정할 때, 제1 맵 캐시 풀(MC_POOL_1)에 대한 캐시 라인의 크기, 제1 맵 캐시 풀(MC_POOL_1)에 캐싱된
맵 데이터에 대한 스트라이프(stripe) 개수 및 설정된 타깃 성능 값을 기초로 할 수 있다. 이하, 도 8 내지 도
9에서 이에 대해 자세히 설명한다.
도 8은 맵 데이터의 타입에 따른 업데이트 당 라이트 사이즈의 일 예를 나타낸 도면이다.
[0150]
도 8을 참조하면, 맵 데이터 중 L2V 데이터는 크기가 4B이고, VPT 데이터는 크기가 4B이고, 저널링 데이터는 크
[0151]
기가 12B이다.

--- [페이지 구분] ---

L2V 데이터가 업데이트될 때, 메모리 컨트롤러(120)는 1개의 L2V 데이터를 리드하고, 리드된 1개의 L2V 데이터
[0152]
에 대해, 해당 L2V 데이터에 저장된 논리 주소와 가상 물리 주소 간의 매핑 정보를 업데이트한 후에 다시 라이
트한다. 따라서 L2V 데이터가 업데이트될 때 L2V 데이터의 라이트 횟수는 1회이다. 따라서, 업데이트 시 L2V 데
이터가 라이트되는 전체 사이즈는 (4B * 1) = 4B이다.
VPT 데이터가 업데이트될 때, 유효한 데이터가 새로운 페이지에 라이트되고 해당 데이터의 이전 버전의 데이터
[0153]
를 저장한 페이지는 더 이상 유효하지 않게 된다. 따라서, 메모리 컨트롤러(120)는 이전에 유효한 페이지를 지
시하던 1개의 VPT 데이터가 유효하지 않은 페이지를 지시하도록 업데이트하고, 새로 유효한 페이지를 지시하는
또다른 1개의 VPT 데이터를 업데이트한다. 따라서, VPT 데이터가 업데이트될 때, VPT 데이터의 라이트 횟수는 2
회이다. 따라서, 업데이트 시 VPT가 라이트되는 전체 사이즈는 (4B * 2) = 8B이다.
저널링 데이터가 업데이트될 때, 변경 정보를 지시하는 1개의 새로운 저널링 데이터가 라이트되고 기존의 저널
[0154]
링 데이터의 변화는 없으므로 저널링 데이터의 라이트 횟수는 1회이다. 따라서, 업데이트 시 저널링 데이터가
라이트되는 전체 사이즈는 (12B * 1) = 12B이다.
도 9는 도 8에서 설명한 맵 데이터의 타입에 따른 타이머 설정의 일 예를 나타낸 도면이다.
[0155]
도 8에서 전술한 바와 같이, 업데이트 시 데이터가 라이트되는 사이즈는 L2V 데이터가 4B, VPT 데이터가 8B, 저
[0156]
널링 데이터가 12B이다.
맵 캐시 풀에 맵 데이터가 캐싱되는 단위인 캐시 라인의 크기는 맵 캐시 풀마다 상이할 수 있다. 도 9에서, L2V
[0157]
데이터가 캐싱되는 맵 캐시 풀의 캐시 라인의 크기는 64B이고, VPT 데이터가 캐싱되는 맵 캐시 풀의 캐시 라인
의 크기는 64B이고, 저널링 데이터가 캐싱되는 맵 캐시 풀의 캐시 라인의 크기는 128B라고 가정한다.
이 경우, L2V 데이터는 한 번 업데이트 시 64B의 캐시 라인 중 4B가 업데이트되므로, 한 번 업데이트시 캐시 라
[0158]
인이 더티(dirty) 상태가 되는 비율인 더티 비율(dirty rate)은 4B/64B = 1/16이 된다.
그리고 VPT 데이터는 한 번 업데이트 시 64B의 캐시 라인 중 8B가 업데이트되므로, 더티 비율은 8B/64B = 1/8이
[0159]
된다.
그리고 저널링 데이터는 한 번 업데이트 시 128B의 캐시 라인 중 12B가 업데이트되므로, 더티 비율은 12B/128B
[0160]
= 3/32이 된다.
이때, 맵 데이터에 대한 스트라이프 개수가 64개이고, 타깃 성능이 1M IOPS라고 가정한다. 맵 데이터에 대한 스
[0161]
트라이프 개수가 64개라는 것은, FTL이 1개의 맵 데이터의 유닛을 64개로 스트라이프(stripe)하여 처리한다는
것을 의미한다. 이 경우 1M IOPS를 만족하기 위해서 1us(=(1/1M)s)마다 64개의 스트라이프된 맵 데이터가 라이
트되어야 한다.
L2V 데이터의 경우 더티 비율이 1/16이므로, 64개의 스트라이프된 맵 데이터가 업데이트될 때, 더티 상태가 되
[0162]
는 캐시 라인의 개수는 64/16 = 4이다. 따라서 1us마다 4개의 캐시 라인이 플러시되어야 하므로 타이머의 값은
1/4us로 설정된다.
VPT 데이터의 경우 더티 비율이 1/8이므로, 64개의 스트라이프된 맵 데이터가 업데이트될 때, 더티 상태가 되는
[0163]
캐시 라인의 개수는 64/8  =  8이다.  따라서 1us마다 8개의 캐시 라인이 플러시되어야 하므로 타이머의 값은
1/8us로 설정된다.
저널링 데이터의 경우 더티 비율이 3/32이므로, 64개의 업데이트 시에 더티되는 캐시 라인의 개수는 64/(32/3)
[0164]
= 6이다. 따라서 1us마다 6개의 캐시 라인이 플러시되어야 하므로 타이머의 값은 1/6us로 설정된다.
이상에서, 각 맵 캐시 풀에 타이머를 설정하는 방법에 대해 설명하였다. 
[0165]
