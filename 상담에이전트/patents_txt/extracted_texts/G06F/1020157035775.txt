에뮬레이션된 공유 메모리(ESM) 구조에서 인터리브드 인터-스레드 파이프라인을 구비하는 멀티-스레드화된 프로
세서의 데이터 메모리(508)의 참조를 처리하기 위한 메모리 장치(500)에 있어서, 상기 메모리 장치는,
멀티스레드화된 실행의 진행중인 단계의 마지막까지 데이터 어레이가 유효한 상태로 유지되는 연상 캐시 메모리
어레이를 형성하는 단계 캐시(504), 상기 메모리 어레이는 데이터 필드를 갖는 다수의 캐시 라인을 포함하고,
각각의 라인은, 바람직하게는 독점적으로, 주소 태그에 대한 데이터 필드 및 주소 태그에 의해 지정된 데이터
메모리 위치를 나타내는 제 1 스레드 id에 대한 데이터 필드를 포함하고, 및
중간 결과와 같은 멀티연산의 내부 데이터를 저장하기 위한 메모리 버퍼를 형성하는 스크래치패드(506)를 포함
하고, 상기 버퍼는, 바람직하게는 독점적으로, 프로세서의 각각의 스레드에 대해 하나의 데이터 필드를 포함하
고,
상기 메모리 장치는 캐시 검색을 위해 단계 캐시(504)에 액세스하고, 프로세서에 의한 데이터 메모리(508)의 참
조를 포함하는 멀티연산의 실행시 프로세서 파이프라인의 다양한 클록 사이클 및 다양한 단계에서 상기 내부 데
이터를 검색 및/또는 저장하기 위해 스크래치패드(506)에 액세스하도록 구성되는 것을 특징으로 하는 메모리 장
치.
청구항 2 
제 1 항에 있어서, 
상기 메모리 장치는, 프로세서의 스레드에 의한 데이터 메모리의 참조에 대응해서, 참조된 메모리 주소와 일치
하는 주소가 내부에 저장된 주소 태그를 근거로 발견되는지를 결정하기 위해 단계 캐시에 액세스하고, 이러한
경우, 일치하는 주소의 단계 캐시 라인의 스레드 id의 데이터 필드에서 스레드 id를 검색하고, 반대로, 캐시 검
색이 오류인 경우, 소정의 데이터 교체 정책을 사용하여 단계 캐시 내의 참조된 메모리 주소에 해당하는 현재
스레드와 주소 태그의 스레드 id를 저장하도록 구성되는 것을 특징으로 하는 메모리 장치.
청구항 3 
제 1 항 또는 제 2 항에 있어서, 
상기 메모리 장치는 스레드에 대해 수신된 메모리 참조 데이터를 저장하기 위한 응답 수신 버퍼(512)를 더 포함
하고, 상기 버퍼는 공유 메모리 시스템으로부터 들어오는 응답 메시지를 수신하도록 구성되는 것을 특징으로 하
는 메모리 장치.
청구항 4 
제 3 항에 있어서, 
상기 응답 수신 버퍼(512)는 멀티포트 버퍼이고, 두 개의 연속적인 단계와 관련된 스레드에 대해 보유 공유 메
모리 참조를 나타내는 데이터 및 보류 필드를 수용하기 위해 두 개의 데이터 어레이와 두 개의 포트를 포함하는
것을 특징으로 하는 메모리 장치.

배 경 기 술
공유 메모리 구조(shared memory architecture, SMA)에서, 데이터와 프로그램 분할은 일반적으로 다수의 스레드
[0002]
(thread)에 의한 처리를 필요로 하는 데이터를 공유 메모리에 배치하고 프로그램을 프로세서에 대해 더욱 독립
적으로 분할함으로써 수행되고, 따라서 처리가 항상 국부적으로 발생하고 이에 따라 프로그래머가 데이터를 이
동시켜야 하는 메시지 패싱 구조(message passing architectures, MPA)에 비해 프로그래밍을 더욱 용이하게 한
다.  불행하게도,  대부분의 SMA은 캐시 일관성(및 이에 따른 지연 허용(latency  tolerance))  및 동시성
(synchronicity) 유지에 비용이 많이 드는 다수의 상호 연결된 프로세서-캐시 쌍으로 구성되는 분산 공유 메모
리 구조를 사용한다. 이는 통신 집중 문제에서 이들의 성능을 심지어 엉망으로 만들 수 있다.
예를 들어, 상기한 문제를 해결하기 위해, 에뮬레이션된 공유 메모리(emulated shared memory, ESM) 또는 공유
[0003]
메모리 에뮬레이션 구조가 도입되었다. 이들은 대용량 통신망을 통해 일반적으로 균일하고 동시에 액세스 가능
한 공유 메모리에 연결되는 일련의 멀티스레드 프로세서를 포함한다. 메모리 시스템에서의 지연은 진행중인 메
모리 참조를 중복시킴으로써 은폐되고, 기계 명령어 수준에서 동시성을 보장하는 특수 저비용 동기화 메커니즘
이 확립된다. ESM 시스템은 실제 하드웨어 구조가 물리적으로 분산된 메모리를 포함하더라도 사용자에게 이상적
인 공유 메모리의 인식을 제공한다. 이론적인 관점에서, 이들 구조는 일반적으로 단순성과 표현성으로 인해 계
산 문제의 본질적인 병렬성(parallelism)뿐만 아니라 병렬 알고리즘의 성능 및 실행 비용을 설명하고 분석하기
위한 모델로서 사용되는 추상적인 병렬 랜덤 액세스 머신(parallel random access machine, PRAM)을 에뮬레이
션하려고 한다. PRAM 모델은 일반적으로 동일한 클록 하에 작동하는 일련의 프로세서 및 이들에 연결된 균일한
단일 단계의 액세스 가능한 공유 메모리를 말한다.
따라서, ESM은 기계 명령어의 실행에서 묵시적인 동기화, 효율적인 지연 은폐 기술, 및 과중한 랜덤 및 동시 액
[0004]
세스 작업량에서도 모든 메모리 참조를 라우팅하는 충분한 대역폭을 제공하기 때문에 칩 멀티프로세서(chip
multiprocessor, CMP)의 프로그래밍 가능성 및 성능 확장성 문제를 해결하는 실현 가능한 기술이다. 프로그래머
가 각각의 전역 메모리 액세스 이후 명백하게 실행의 스레드를 동기화할 필요는 없지만 이를 자동으로 처리하는
하드웨어에 의존할 수 있는 반면, 예를 들어, 메시지 패싱 구조(MPA)에서, 프로그래머는 통신을 명백하게 정의
하고, 서브태스크(subtask)를 동기화하며, MPA의 프로그래밍을 어렵게 하는 스레드 간에 데이터 및 프로그램 분
할을 설명해야 하기 때문에 동시 실행은 프로그래밍을 더욱 용이하게 하는 것으로 간주된다. 공유 메모리 에뮬
레이션에서 사용되는 지연 은폐는 대용량 계산 기법을 이용하고, 여기서 하나의 스레드가 전역 공유 메모리를
참조하는 동안 그 밖의 스레드가 실행된다. 대용량 계산 기법은 사용 가능한 스레드 레벨의 병렬성으로부터 추
출된 병렬 여유성(parallel slackness)을 사용하기 때문에, 스누핑(snooping) 또는 디렉토리 기반의 캐시 일관
성 메커니즘에 의존하고 따라서 제한된 대역폭 또는 디렉토리 액세스 지연 및 과중한 일관성 트래픽 유지에 시
달리는 종래의 대칭적 멀티프로세서와 불균일 메모리 액세스(non-uniform memory access, NUMA) 시스템에 비해
향상된 확장성을 제공하는 것으로 간주된다.
최근, 특정한 경우에 대수 인자에 의해 프로그래밍을 더욱 단순화하고 성능을 향상시키는, PRAM의 동시 읽기 동

치패드 단계 캐시 단위(S1, S2, S3, ..., Sp (106))를 확립할 수 있다.
검토한 솔루션의 한 가지 근본적인 사상은 실제로 인터리브드 방식으로 효율적으로 실행되고 네트워크의 지연을

따라, 실행되는 스레드는 변경되고 다음 스레드가 이의 메모리 요청 등을 할 수 있다. 스레드가 다시 실행되기
전에 메모리 참조의 응답이 프로세서 코어로 도착되면 메모리 지연은 발생하지 않을 것이다. 이는 네트워크의
대역폭이 매우 충분해야 하고, 파이프라인 메모리 액세스 트래픽 내에 핫스팟이 방지될 수 있는 것을 필요로 한

수 있다.

[0016]
상기한 바와 같이 각각의 참조된 메모리 위치에 대한 첫 번째 참조를 제외한 모든 것을 프로세서 방식으로 그리
고 단계적으로 필터링함으로써 캐시 일관성 문제 없이 공유 메모리(408)로의 CRCW 액세스를 구현하기 위해 사용
된다. 각각의 캐시 라인은 바람직하게, 데이터, 개시자(initiator, 주소로 지정된 위치를 나타내는 제 1 스레드
의 스레드 id), 및 주소 태그를 포함한다. MU 다른 단계에 속하는 스레드를 전달할 수 있는 파이프라인의 전송
및 수신 단계 모두로부터의 단계 캐시를 MU가 액세스할 필요가 있기 때문에 두 개의 캐시 어레이와 두 개의 포
트가 필요하다.
프로세서가 메모리(408)를 참조할 때마다, 단계 캐시 검색이 수행된다. 라인이 사용 중이고, 주소가 해당 라인
[0017]
의 주소 태그와 일치하며, 참조의 현재 단계의 최하위 비트(least significant bit, LSB)가 해당 라인의 단계의
두 개의 LSB와 일치하는 경우 해당 캐시 라인에 대해 검색이 검출된다. 검색이 성공한 경우, 쓰기는 바로 무시
되는 반면, 캐시로부터 데이터에 액세스함으로써 읽기가 바로 완료된다. 검색 오류의 경우, 참조는 교체 정책
(replacement policy)을 사용하여 캐시에 저장되고 보류(읽기를 위해)로 표시된다. 캐시 라인에 참조 정보를 저
장하는 것과 동시에, 참조 그 자체가 공유 메모리 시스템(408)으로 전송된다. 메모리 시스템(408)으로부터 읽기
의 응답이 도착하면, 데이터는 참조 정보를 저장하고 있는 단계 캐시 라인의 데이터 필드로 입력되고, 보류 필
드는 지워진다. 단계 필드가 다시 현재 단계의 최하위 비트와 일치하기 전에 라인을 무효화하기 위해 소정의 캐
시 붕괴 논리(cache decay logic)가 이용된다.
별도의 이중 포트 프로세서 수준의 멀티연산 메모리인 제한된 연관성의 단계 캐시로 멀티(-프리픽스)연산을 구
[0018]
현하기 위해, 스크래치패드(406)가 사용된다. 참조에 대한 정보를 단계 캐시로부터 제거시킬 수 있는 가능한 충
돌과는 무관하게 정보를 저장하는 저장소에 단계 캐시에 대한 각각의 멀티연산 시퀀스의 개시자 스레드의 id 및
내부 개시 스레드 id의 레지스터뿐만 아니라 참조 정보를 저장할 필요가 있기 때문이다. 스크래치패드(406)는
프로세서의 각각의 스레드에 대해 데이터, 주소 및 보류용 필드를 갖는다. 단계 캐시(404)에 쓰여질 데이터가
스크래치패드(406)에도 쓰여지고, 특정 위치를 나타내는 제 1 스레드의 id가 단계 캐시(404)와 개시자 레지스터
(나머지 참조를 위해)에 저장되고, 멀티연산에 대한 보류 비트가 스크래치패드(406)에 유지되고, 응답 데이터가
스크래치패드(406)에 저장되며, 연산을 종료하기 위한 응답 데이터가 스크래치패드(406)로부터 검색되도록 두
개의 명령어의 시퀀스를 사용하여 멀티연산이 구현될 수 있다(아래의 표 1의 알고리즘 1 참조).

Search Write_Address from the StepCache and put the result in matching_index
IF not found THEN
   IF the target line pending THEN
      Mark memory system busy until the end of the current cycle
   ELSE Read_data := 0
      StepCache[matching_index].data := Write_data
      StepCache[matching_index].address := Write_Address
      StepCache[matching_index].initiator_thread := Thread_id
      ScratchPad[Thread_id].Data := Write_data
      ScratchPad[Thread_id].Address := Write_Address
      Initiator_thread:=Thread_id
ELSE
   Read_data := StepCache[matching_index].data
   StepCache[matching_index].data:= Write_data + Read_data
   ScratchPad[Initiator_thread].Data := Write_data + Read_data
   Initiator_thread := StepCache[matching_index].Initiator_thread

IF Thread_id<>Initiator_thread THEN
   IF ScratchPad[Initiator_thread].pending THEN
      Reply_pending := True
   ELSE
      Read_data := Write_data + ScratchPad[Initiator_thread].Data
ELSE

      Send a EMPADD reference to the memory system with
      - address = Write_Address
         - data = ScratchPad[Initiator_thread].Data
      ScratchPad[Thread_id].pending := True

로세서 방식의 멀티연산 결과를 이용하여 외부 메모리 참조를 실행시키도록 한다. 동일한 위치를 대상으로 하는
외부 메모리 참조는 멀티연산의 유형에 따라 해당 메모리 모듈의 활성 메모리 장치에서 처리될 수 있고, 참여
프로세서의 스크래치패드로 다시 응답 데이터가 전송된다.
동시 액세스 ESM 시스템의 대안적인 실현은 레너드의 알고리즘(Ranade's algorithm) 또는 실제 멀티포트 메모리
[0021]
의 캐시리스(cacheless) 변형을 사용한다: 레너드의 알고리즘은 물리적 분산 메모리 시스템 상의 메모리 참조의
분류 및 전달을 기반으로 공유 메모리 추상을 구현한다. 이 솔루션은 신속한 멀티프리픽스 연산(MCRCW PRAM 모
델)을 구현할 수 있는 능력과 같은 일부 장점을 제공하지만, 이는 또한 모든 액세스가 복잡한 하드웨어 분류기
를 필요로 하는 연속적인 분류 및 액세스 단계 및 네트워크의 노드에 대한 결합된 참조를 저장하기 위한 버퍼를
포함하기 때문에 개선의 여지를 남긴다. 또한, 기존의 구조는 비확장형 상호 연결 토폴로지를 필요로 한다. 실
제 멀티포트 메모리는 각각의 메모리 셀 어레이의 액세스 회로를 동시 메모리 포트의 수만큼 복제함으로써 메모
리 셀 수준까지의 동시 액세스를 제공한다. 이는 포트의 수(셀의 크기는 오직 선형으로만 증가함)에 대해 이차
적으로 액세스 회로가 차지하는 면적을 증가시키며, 포트의 수가 예를 들어 네 개를 초과하는 경우 이를 불가능
하게 한다. 캐시 일관성은 효율적인 공유 메모리 알고리즘을 이용하여 유지하는 것이 적어도 멀티포트 메모리만
큼 매우 비싸기 때문에, 캐시가 프로세서 다음에 위치하는 일반적인 캐시 기반 구조는 고급 공유 메모리 연산에
서 사용될 수 없다.

메모리 장치는,
멀티스레드화된 실행의 진행중인 단계의 마지막까지 데이터 어레이가 유효한 상태로 유지되는 연상 캐시 메모리
[0025]
어레이를 형성하는 단계 캐시, 상기 메모리 어레이는 데이터 필드를 갖는 다수의 캐시 라인을 포함하고, 각각의
라인은, 바람직하게는 독점적으로, 주소 태그에 대한 데이터 필드 및 주소 태그에 의해 지정된 데이터 메모리
위치를 나타내는 제 1 스레드 id에 대한 데이터 필드를 포함하고, 및
중간 결과와 같은 멀티연산의 내부 데이터를 저장하기 위한 메모리 버퍼를 형성하는 스크래치패드를 포함하고,
[0026]
상기 버퍼는, 바람직하게는 독점적으로, 프로세서의 각각의 스레드에 대해 하나의 데이터 필드를 포함하고,
상기 메모리 장치는 캐시 검색을 위해 단계 캐시에 액세스하고, 프로세서에 의한 데이터 메모리의 참조를 포함
[0027]
하는 멀티연산의 실행시 프로세서 파이프라인의 다양한 클록 사이클 및 다양한 단계에서 상기 내부 데이터를 검
색 및/또는 저장하기 위해 스크래치패드에 액세스하도록 구성된다.
일 실시형태에서, 상기 메모리 장치는, 프로세서의 스레드에 의한 데이터 메모리의 참조에 대응해서, 참조된 메
[0028]
모리 주소와 일치하는 주소가 내부에 저장된 주소 태그를 근거로 발견되는지를 결정하기 위해 단계 캐시에 액세
스하고, 이러한 경우, 즉, 단계 캐시가 검색된 경우, 일치하는 주소의 단계 캐시 라인의 스레드 id의 데이터 필
드에서 스레드 id를 검색하고, 반대로, 캐시 검색이 오류인 경우, 소정의 데이터 교체 정책을 사용하여 단계 캐
시 내의 참조된 메모리 주소에 해당하는 현재 스레드와 주소 태그의 스레드 id를 저장한다. 
또 다른, 바람직하게는 추가적인 실시형태에서, 상기 메모리 장치는 스레드에 대해 수신된 메모리 참조 데이터
[0029]
를 저장하기 위한 응답 수신 버퍼를 더 포함한다. 상기 버퍼는 공유 메모리 시스템으로부터 들어오는 (응답) 메
시지를 수신하도록 구성된다.
상기 응답 수신 버퍼는 멀티포트 버퍼이고 두 개의 연속적인 단계와 관련된 데이터 및 예를 들어 "보류" 필드를
[0030]
수용하기 위해, 예를 들어, 두 개의 데이터 어레이와 두 개의 포트를 포함할 수 있으며, 이에 따라 상기 버퍼는
적어도 함축적으로 단계-인식 또는 단계 지정 가능하다.

다양한 실시형태에서, 단계 데이터는 예를 들어 스레드별(thread-specific) 데이터 필드 또는 레지스터를 사용
[0031]
하여 저장될 수 있다. 또한 메모리 참조 메시지는 바람직하게 단계 데이터용 필드를 포함한다.
또 다른 실시형태에서, 상기 메모리 장치는 메모리 쓰기 또는 읽기 연산과 관련해서 단계 캐시 검색이 오류인
[0032]
경우 각각 응답 수신 버퍼를 통해 참조된 데이터를 내부에 저장하거나 검색하기 위한 공유 메모리 시스템으로
메모리 참조를 전송하고, 쓰기 연산과 관련해서 단계 캐시가 검색된 경우 쓰기 연산을 무시하며, 읽기 연산과
관련해서 단계 캐시가 검색된 경우 검색되거나 저장된 스레드 id와 함께 응답 수신 버퍼로부터 결과를 획득하도
록 구성된다.
또 다른 실시형태에서, 상기 메모리 장치는 멀티 연산과 관련해서 스크래치패드를 액세스하고, 즉, 스크래치패
[0033]
드에 데이터를 저장하고 스크래치패드에서 데이터를 검색하며, 내부 프로세서 멀티연산 결과를 계산하기 위해
검색된 또는 저장된 스레드 id와 함께 이를 공유 메모리 시스템에 전송하도록 구성되며,
상기 메모리 장치는 최종 멀티연산 결과(멀티-프리픽스)를 결정하기 위해 공유 메모리 시스템으로부터 응답 수
[0034]
신 버퍼에서 수신된 데이터 및 상기 내부 프로세서 결과 모두를 이용하도록 더 구성될 수 있다.
또 다른 실시형태에서, 본원에서 설명되는 단계 캐시에 액세스하도록 구성되는 해시 및 구성 장치를 구비한다.
[0035]
상기 해시 및 구성 장치는 바람직하게 액세스 포트를 통해, 더욱 바람직하게는 해시 및 구성 장치의 전용으로
구성되는 단일 액세스 포트를 통해 상기 단계 캐시에 결합된다. 상기 해시 및 구성 장치는 (예를 들어, 연산 레
지스터에서) 프로세서에 의한 메모리 연산, (예를 들어, MAR 레지스터에 정해진) 메모리 주소, (예를 들어, MDR
레지스터에 정해진) 메모리 데이터, 스레드 id, 단계 카운터의 소정 수의 최하위 비트(LSB), 및 단계 캐시 액세
스의 결과(즉, (검색이 성공인지 오류인지 여부에 따라 캐시 검색의 결과의 특성)로 이루어진 군에서 선택되는
적어도 하나의 요소를 기반으로 메모리 참조 메시지를 구성하도록 구성될 수 있다.
일부 실시형태에서, 상기 단계 캐시는 멀티-웨이 집합 연산(multi-way set associative) 단계 캐시일 수 있다. 
[0036]
일부 추가적인 또는 대안적인 실시형태에서, 상기 주소는 예를 들어 랜덤하게 선택된 해싱 함수를 이용하여 해
[0037]
싱될 수 있다. 상기 HCU는 이후 메모리 참조에 대한 해시 주소를 계산하기 위해 이용된다.
또 다른 실시형태에서, 상기 메모리 장치는 본원에서 설명되는 스크래치패드에 액세스하도록 구성되는 메모리
[0038]
요청 전송 로직 개체를 구비한다. 상기 스크래치패드는 액세스 포트를 통해, 바람직하게는 전송 로직 개체의 전
용으로 구성될 수 있는 단일 액세스 포트를 통해 액세스될 수 있다.
상기 전송 로직 개체는 해시 및 구성 장치에 의해 제공된 메모리 메시지에 따라 공유 메모리 시스템에 메모리
[0039]
참조를 전송하도록 구성될 수 있다. 메모리 연산을 기반으로, 상기 전송 로직은 멀티연산의 중간 결과 또는 내
부 프로세서 결과를 결정하고, 바람직하게는 메모리 응답 대기 큐를 통해 응답 수신 버퍼에 대해 (신속한) 응답
으로서 내부 메모리 (멀티)연산의 결과와 같은 내부 데이터를 제공하도록 구성될 수 있다. 
실제로, 관련된 실시형태에서, 상기 메모리 장치는 소정 수의 파이프라인 단계와 관련된 응답 대기 큐를 더 포
[0040]
함하고, 상기 큐는, 예를 들어, 전송 논리로부터의 신속한 응답이 응답 수신 버퍼에 대해 적절한 순서로 전달되
어 공유 메모리로부터 수신된 관련 메모리 참조를 적시에 검색한 후 수신 ALU를 이용하여 최종 연산 결과를 도
출할 수 있도록, 메모리 요청 전송 로직 객체와 응답 수신 버퍼를 연결한다.
또 다른 양태에 따라, 에뮬레이션된 공유 메모리(ESM) 구조에서 인터리브드 인터-스레드 파이프라인을 구비하는
[0041]
멀티-스레드화된 프로세서의 데이터 메모리의 참조를 처리하기 위한 방법이 제공되고, 상기 방법은,
멀티스레드화된 실행의 진행중인 단계의 마지막까지 데이터 어레이가 유효한 상태로 유지되는 연상 캐시 메모리
[0042]
어레이를 형성하는 단계 캐시(504)를 획득하는 단계, 상기 메모리 어레이는 데이터 필드를 갖는 다수의 캐시 라
인을 포함하고, 각각의 라인은, 바람직하게는 독점적으로, 주소 태그에 대한 데이터 필드 및 주소 태그에 의해
지정된 데이터 메모리 위치를 나타내는 제 1 스레드의 스레드 id에 대한 데이터 필드를 포함하고,
중간 결과와 같은 멀티연산의 내부 데이터를 저장하기 위한 메모리 버퍼를 형성하는 스크래치패드(506)를 획득
[0043]
하는 단계, 상기 버퍼는, 바람직하게는 독점적으로, 프로세서의 각각의 스레드에 대해 하나의 데이터 필드를 포
함하고,
캐시 검색을 위해 상기 단계 캐시에 액세스하고, 프로세서에 의한 데이터 메모리의 참조를 포함하는 멀티연산의
[0044]
실행시 프로세서 파이프라인의 다양한 클록 사이클 및 다양한 단계에서 상기 내부 데이터를 검색 및/또는 저장
하기 위해 스크래치패드에 액세스하는 단계를 포함한다.

본 기술분야의 숙련자가 이해할 수 있는 바와 같이, 본원에 제시된 메모리 장치의 다양한 실시형태에 관한 다양
[0045]
한 고려가 필요한 부분만 약간 수정하여 방법의 실시형태에 유연하게 적용될 수 있고 반대의 경우도 마찬가지이
다.
본 발명의 유용성은 이의 각각의 특정 실시형태에 따라 다수의 주제로부터 발생한다. 일반적으로, 하나의 메모
[0046]
리 주소에 대한 동시적인 메모리의 참조는, 각각의 프로세서에 의한 참조가 멀티스레드화된 실행의 단일 단계
동안 바람직하게 하나로 감소될 수 있도록 단계 캐시에 의해 구현된다. 멀티(-프리픽스)연산의 중간 데이터를
저장하기 위해 스크래치패드 메모리가 이용된다.
해당 액세스(파이프라인) 단계, 액세스 요소 및 내부에 저장된 데이터에 대해 본원에 개시된 바와 같은 단계 캐
[0047]
시와 스크래치패드의 특징 및 원래의 메모리 장치의 변경을 통해,  상당히 단순화된 하드웨어 구현이
달성되었고, 여기서 단계 캐시의 면적은 이전에 공개된 버전의 25% 이하로 축소할 수 있고, 스크래치패드의 면
적도 그에 따라 감소되고, 단계 캐시와 스크래치패드 내의 제 2 포트는 제거되고, 많은 수의 비교기를 구비하는
복잡한 수신 응답 논리가 더욱 단순한 수신 버퍼로 교체되며, 다양한 클록 사이클 동안 변경된 단계 캐시와 스
크래치패드를 모두 액세스함으로써 클록 사이클을 단축시킨다.
"소정 수"라는 표현은 본원에서, 예를 들어, 하나, 둘, 또는 셋과 같이 하나(1)에서 시작하는 임의의 양의 정수
[0048]
를 나타낸다.
"다수"라는 표현은 본원에서, 예를 들어, 둘, 셋, 또는 넷과 같이 둘(2)에서 시작하는 임의의 양의 정수를 나타
[0049]
낸다.
"멀티연산"이라는 용어는 본원에서 일반적으로 실제 멀티-프리픽스 또는 그 밖의 해당 연산과 같이 그러나 멀티
[0050]
-프리픽스와는 대조적으로 프로세서에 다시 전송되는 반환값, 즉, 그에 따라 변경되는 대상 메모리 위치의 내용
을 갖지 않는 연상 누적 연산을 칭한다.
본 발명의 다양한 실시형태가 첨부한 청구항에 개시된다.
[0051]
도면의 간단한 설명
다음, 본 발명은 첨부한 도면을 참고로 더욱 상세하게 설명된다, 도면에서:
[0052]
도 1은 실리콘 플랫폼 상에서 공유 메모리를 에뮬레이션하기 위한 실현 가능한 확장형 구조의 블록도이다.
도 2는 실현 가능한 ESM 구조, 본질적으로는 CMP ESM 구조의 또 다른 도면이다.
도 3은 MCRCW ESM 프로세서의 일 실시형태의 고차원 블록도 및 파이프라인이다.
도 4는 MCRCW ESM CMP 구조에서 프로세서의 메모리 장치의 종래 기술 버전을 도시하고 있다.
도 5는 본 발명에 따른 ESM 구조를 위한 메모리 장치의 일 실시형태를 도시하고 있다.
도 6은 본 발명에 따른 방법의 일 실시형태를 도시하고 있다.
발명을 실시하기 위한 구체적인 내용
본 발명의 일 실시형태에 따른 메모리 장치(MU)는 일반적으로, 예를 들어, 전용 명령어 메모리, 연상 단계 캐시
[0053]
(단계-인식 교체 정책에 의해 관리되는 멀티스레드화된 실행의 진행중인 단계의 마지막까지 내부에 삽입되는 데
이터를 보유함) 및 프로세서에 부착된 비연상(스레드-어드레스) 스크래치패드 버퍼, 및 멀티-메시(multi-mesh)
상호 연결 네트워크와 같은 고대역 네트워크를 통해 프로세서(코어)에 결합되는, 물리적으로 분산되었지만 논리
적으로 공유된 데이터 메모리를 포함하는 칩 멀티프로세서(CMP) 또는 멀티프로세서 시스템 온 칩(MP-SOC) 시스
템을 구현하기 위해 ESM 컴퓨터 구조와 관련하여 사용될 수 있다. 네트워크는 충분히 높은 가능성으로 임의의
통신 패턴에 대해 충분한 처리량 및 상당한 지연이 달성될 수 있도록 프로세서를 분산 메모리 모듈에 연결한다.
코드의 읽기 전용 부분에 대한 처리량을 최대화하기 위해, 프로세서에서 메모리로 가는 참조 및 메모리에서 프
